コピー・写真・レイアウトを足すときも直すときも、

## 1. どこに何があるか

| 中身 | 場所 |

片方だけ直して見た目がずれる、ということは起きない。

## 2. 投稿の進め方

**9枚そろうまで待たなくていい。** 01から順に出していけば、
グリッドは投稿するたびに完成に近づいていく。

止まったときは、次に出す1枚だけを見る。

| No | 出せる状態か | 出す前に必要なこと |
| --- | --- | --- |
| 01 | **出せる** | なし |
| 02 | **出せる** | なし（写真を使わない回） |
| 03 | 出せる | 「17日間で3カ国」の事実確認。写真は差し替え推奨（任意） |
| 04 | **出せる** | なし（写真を使わない回） |
| 05 | **出せる** | なし（写真を使わない回） |
| 06 | **出せる** | なし |
| 07 | **出せる** | なし |
| 08 | **出せる** | なし（写真を使わない回） |
| 09 | **出せる** | なし |

写真を使わない回（02・04・05・08）は素材待ちが発生しない。
つまり**素材が揃っていなくても止まらない**ように9枚を組んである。

投稿の間隔は決めていない。物語の順番だけ守れば、
毎日でも週2回でも、グリッドは崩れない。

## 3. 作業の流れ

```bash
npm run dev          # /instagram9 で9枚まとめて確認
npm run ig:render    # PNGを書き出す（public/instagram/）
npm run ig:render 01 # 番号を指定して1枚だけ
npm run ig:fonts     # 表紙のコピーに新しい漢字を足したときだけ
```

`ig:render` は Playwright を使う。入っていなければ `npm i -D playwright` を先に。
サイト本体のビルドには関係しないので、依存には入れていない。

`ig:fonts` は、表紙に出る文字だけに絞ったフォントを取り込み直す。
ひらがな・カタカナ・英数字は最初から全部入っているので、
表紙コピーに**新しい漢字**を足したときだけ実行すればよい。

流し忘れても大丈夫なようにしてある。
`ig:render` は書き出す前にフォントの文字を確認し、
足りない文字があればその文字を挙げて止まる（豆腐のまま書き出されることはない）。

## 4. 01で確定したルール（02〜09で固定）

制作手順の指示どおり、01でこれを決め、以降は変えていない。

| 項目 | 確定値 |
| --- | --- |
| キャンバス | 1080 × 1350（4:5） |
| 余白 | 左右 90px ／ 上下 96px |
| 番号 | **表紙には入れない**（下記） |
| カテゴリー | 上左・くすみゴールドの罫線の下・17px / トラッキング .34em・**1枚に1つだけ** |
| コピー | **全変型で下寄せ**・Noto Serif JP 300 / 68〜92px / 行送り1.5 |
| サブコピー | 25px / 行送り1.9 |
| フッター | 「仕事を軽くして、人生を広げる。」＋ BLOOM LINK（くすみゴールド） |
| フッター（09のみ） | シリーズの一文 ＋ 「Rie」の署名（Italianno） |
| 基本色 | IVORY `#FAF8F3` / WHITE / NAVY `#2B5F7A` / CHARCOAL `#3A4754` |
| アクセント | くすみゴールド `#C9A96E`（上左の罫線・08の数字・BLOOM LINK のみ・少量） |
| 写真加工 | `saturate(1.04) brightness(1.03)` のみ。**暗くしない** |

**コピーが下寄せであること**が、9枚を1つの作品に見せている一番の要素。
変型ごとに上寄せ・中央寄せへ変えない。

レイアウトは絶対座標ではなく縦のフレックスで組んである。
コピーの行数を増やしても写真と文字は重ならず、写真側が自動で縮む。

### 写真の上に文字を置くとき

暗いフィルター＋白文字には**戻さない**。
明るいアイボリー面を重ねて、紺文字を読ませる（`.ig-veil-*`）。
上のアイボリー帯は212pxで、ここを削るとカテゴリー名が写真に埋もれる。

## 5. グリッド設計

9枚を並べた状態そのものを1つの作品として設計している。
同じ型が縦にも横にも隣り合わないように配置した。

```
01 額装      02 文字のみ   03 写真全面
04 手順の図  05 問いの列   06 額装
07 3枚組     08 数字       09 着地
```

- **額装** — アイボリー地に写真をはめる。余白そのものがデザイン
- **写真全面** — 全面写真＋明るいアイボリー面
- **帯 / 3枚組** — 左右いっぱいの写真。額装との対比でリズムをつくる
- **文字のみ / 手順の図 / 問いの列 / 数字** — 写真を使わず、タイポグラフィで持たせる

### 表紙に番号を入れない理由

当初は全枚に 01〜09 の番号を入れていたが、外した。

**Instagramのプロフィールは新しい投稿が左上に来る。**
01から順に投稿すると、グリッド上では番号がこう並ぶ。

```
09 08 07
06 05 04
03 02 01
```

番号が逆から読まれ、はじめて見た人には左上の「09」が何なのかわからない。
順番はキャプション冒頭の「01｜」で伝えることにして、表紙からは外した。
表紙に残したのはカテゴリー名（LIFE / ABOUT ME / GLOBAL …）だけ。

戻したいときは `cardHTML(post, { numbers: true })` の既定値を変えれば戻る。

投稿前に見るべきグリッドは `grid-instagram.png`（実際の並び）のほう。
`grid.png` は物語の順で、設計を確認するためのもの。

### 04と05の分担

隣り合う2枚なので、役割をはっきり分けている。

| | 04 HOW I WORK | 05 AI & SYSTEM |
| --- | --- | --- |
| 見せるもの | **動作**（何をするか） | **問い**（何を決めるか） |
| 中身 | 整理する → やめる → 任せる → 仕組みにする | 何を残す／AIに／人に／自分が |
| 形 | 線画アイコンの**横**並び | 罫線で区切った**縦**の列 |

「やめる」は04の担当なので、05の問いからは外してある。
縮小して並べたときに別物として読めるよう、横組みと縦組みで分けている。

中央の列（02・05・08）が文字ものになり、写真が外側の列に回る。
9枚を縮小して見たときに、これが縦の背骨として効く。

1枚直すたびに、必ず `/instagram9` か `grid-instagram.png` に戻って全体を見る。

### 型に合う写真の向き

**どの型に入れるかで、選ぶ写真が変わる。**

| 型 | 枠の形 | 向いている写真 |
| --- | --- | --- |
| 写真全面（03） | 上半分だけが見える | 被写体が**画面の上寄り**にある写真 |
| 額装（01・06） | 900×560の横長 | 横位置、または被写体が中央の写真 |
| 3枚組（07） | 約358×560の縦長×3 | **スマホの縦写真がそのまま使える** |
| 帯（09） | 1080×430の横長 | 水平線・街並みなど横に広がる写真 |

縦長写真を横長の枠に入れると被写体が枠の外へ出るので、
`focus`（1枚もの）と `focusBy`（3枚組）で残す位置を指定できるようにしてある。
指定は `'50% 78%'` のような object-position の書き方。

### 写真の取り込み方

スマホから上げた写真は5〜8MBある。そのままだとリポジトリとサイトが重くなるので、
長辺2000pxへ落として名前を付け直す。撮影時の向き（EXIF）もここで焼き込まれる。

```bash
npm run ig:photo public/travel/IMG_0237.jpeg uzbekistan-market.jpg
```

### 写真の解像度（実測）

`object-fit: cover` の拡大率を実測した結果。**問題は03の1枚だけ。**

| No | ファイル | 元データ | 描画領域 | 倍率 | 判定 |
| --- | --- | --- | --- | --- | --- |
| 01 | `japan.jpg` | 622×800 | 900×560 | 1.45x | そのままで可 |
| 03 | `barcelona.jpg` | 450×800 | 1080×1350 | **2.40x** | **差し替え推奨** |
| 06 | `pergola.jpg` | 1500×2000 | 900×560 | 0.60x | そのままで可 |
| 07 | `uzbekistan-khiva.jpg` | 1125×2000 | 358×560 | 0.32x | そのままで可 |
| 07 | `uzbekistan-market.jpg` | 1125×2000 | 358×560 | 0.32x | そのままで可 |
| 07 | `hawaii.jpg` | 601×800 | 358×560 | 0.70x | そのままで可 |
| 09 | `malta.jpg` | 900×507 | 1080×430 | 1.20x | そのままで可 |

**同じ写真でも、入れる枠によって必要な解像度が変わる。**
3枚組の列（358px幅）は元データが小さくても足りるが、
写真全面（1080px幅）だけは元データの幅がそのまま効く。

### 差し替えが必要なもの

**投稿を止めているものは無い。以下はすべて任意。**

1. **03（GLOBAL）の写真** — 唯一の実害。3点ある。
   - 2.4倍に引き伸ばしていて、拡大すると軟らかい
   - 元データ自体に暗い矩形のノイズが焼き付いている（画面下中央）
   - グラスを持っている（05で外した判断と揃えるなら要検討）

   写真全面の型は**上半分しか見えない**ので、
   代わりの写真も被写体が画面の上寄りにある必要がある。
   手持ちの他の写真（ウズベキスタンの2枚など）は被写体が下寄りで、
   この枠に入れると本人がアイボリー面に隠れてしまう。
   **バルセロナの元データか、上寄り構図の別カットが1枚あれば解決する。**
   03を投稿する前までに間に合えばよい。

2. **01（LIFE）の写真** — 画質は問題ない（1.45倍）。
   ただし正装の着物＋和風建築の門構えは**料亭の女将**に読める。
   コピーが「妻。母。娘。会社員22年。店の経営。」＝*全部*なのに、
   写真は一番格式のある一つの役割しか写っていない。
   9枚の中で唯一の和・正装なので色調も浮きやすい。

   欲しいのは**普段着の日常の場面**（後ろ姿や手元でも可）。
   額装の型なので横位置か被写体が中央のもの。
   例: 食卓、キッチン、駅のホーム、子どもと歩いている、PCと湯呑み。
   **無理に用意しなくてよい。着物のままでも投稿できる。**
   着物の写真は捨てない。日本を扱う回ができたときの候補。

3. **06（PEOPLE）の写真** — 解決済み。`pergola.jpg` は高解像度で問題ない。
   チームが写った仕事の写真があればさらに良くなるが、**必須ではない**。

4. **インド** — リポジトリに写真がない。ウズベキスタンは07に入った。

5. **05（AI & SYSTEM）** — 当初は `windowseat.jpg`（機内・PC）を想定したが、
   写り込んでいるものがビジネスアカウントの1枚目としては判断が要るため外し、
   「AIに渡す前に決める4つの問い」を見せる文字ものにした。
   トリミングでは外せない（瓶とグラスが画面中央にあり、左端のPCしか残らない）。
   仕事風景の写真が用意できれば、帯の型に戻すこともできる。

### 事実確認が必要なコピー

03のサブコピー「17日間で3カ国へ。それでも、仕事は止まらなかった。」は、
別案から取り込んだ数字。**実際の日数・カ国数と合っているか確認してから投稿する**こと。

## 7. 本文（キャプション）

9本とも `src/instagram9/posts.js` に入っている。
`/instagram9` の各投稿に「本文をコピー」ボタンがあり、ハッシュタグまで含めてそのままコピーできる。

ハッシュタグは共通8個＋投稿ごとに2個。共通部分は `hashtagsBase` で一括で直せる。

本文を書くときに守っていること:

- 脱サラ成功物語にしない。会社員時代を否定しない（02）
- 海外ノマド自慢・旅行自慢にしない（03・07）
- AIコンサルアカウントのように見せない。AIは手段として書く（05）
- 数字だけの実績自慢にしない。結論を見せる（08）
- 苦労話に寄せない。40代女性向けだけに狭めない

## 8. やらないこと

- 全体を暗くする／黒中心にする／「高級感＝暗い」と解釈する
- 写真を暗く加工して、無理に統一感を作る
- AI生成写真を中心にする
- 9枚すべてを同じテンプレートにする
- 01〜09を独立した投稿として設計する
- 途中でブランドカラーや軸を変更する
- 英語をデザイン目的で増やす（主役は日本語。英字カテゴリーは1枚に1つまで）
