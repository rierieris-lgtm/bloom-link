## 2. 投稿の進め方

**9枚そろうまで待たなくていい。** 01から順に出していけば、
グリッドは投稿するたびに完成に近づいていく。

止まったときは、次に出す1枚だけを見る。

| No | 出せる状態か | 出す前に必要なこと |
| --- | --- | --- |
| 01 | **出せる** | なし |
| 02 | **出せる** | なし（写真を使わない回） |
| 03 | **出せる** | なし（事実確認が要る数字は外した） |
| 04 | **出せる** | なし（写真を使わない回） |
| 05 | **出せる** | なし |
| 06 | **出せる** | なし |
| 07 | **出せる** | なし |
| 08 | **出せる** | なし（写真を使わない回） |
| 09 | **出せる** | なし |

写真を使わない回（02・04・08）は素材待ちが発生しない。
**素材が揃っていなくても止まらない**ように9枚を組んである。

投稿の間隔は決めていない。物語の順番だけ守れば、
毎日でも週2回でも、グリッドは崩れない。

## 3. 作業の流れ

```bash
npm run dev          # /instagram9 で9枚まとめて確認
npm run ig:render    # PNGを書き出す（public/instagram/）
npm run ig:render 01 # 番号を指定して1枚だけ
npm run ig:fonts     # 表紙のコピーに新しい漢字を足したときだけ
```

`ig:render` は Playwright を使う。入っていなければ `npm i -D playwright` を先に。
サイト本体のビルドには関係しないので、依存には入れていない。

`ig:fonts` は、表紙に出る文字だけに絞ったフォントを取り込み直す。
ひらがな・カタカナ・英数字は最初から全部入っているので、
表紙コピーに**新しい漢字**を足したときだけ実行すればよい。

流し忘れても大丈夫なようにしてある。
`ig:render` は書き出す前にフォントの文字を確認し、
足りない文字があればその文字を挙げて止まる（豆腐のまま書き出されることはない）。

## 4. 01で確定したルール（02〜09で固定）

制作手順の指示どおり、01でこれを決め、以降は変えていない。

| 項目 | 確定値 |
| --- | --- |
| キャンバス | 1080 × 1350（4:5） |
| 余白 | 左右 90px ／ 上下 96px |
| 番号 | **表紙には入れない**（下記） |
| カテゴリー | **見出しの直上**・17px / トラッキング .34em・**1枚に1つだけ** |
| コピー | Noto Serif JP 300 / 74〜84px / 行送り1.5。置き場所は下・上・箱の3種（§5） |
| サブコピー | 25px / 行送り1.9 |
| フッター | 「仕事を軽くして、人生を広げる。」＋ BLOOM LINK（くすみゴールド） |
| フッター（09のみ） | 「Rie」の署名のみ（Italianno）。コピー自体がシリーズの一文なので繰り返さない |
| 基本色 | IVORY `#FAF8F3` / WHITE / NAVY `#2B5F7A` / CHARCOAL `#3A4754` |
| アクセント | くすみゴールド `#C9A96E`（見出しとサブの間の罫線・08の数字・BLOOM LINK のみ・少量） |
| 写真加工 | `saturate(1.04) brightness(1.03)` のみ。**暗くしない** |

**カテゴリー → 見出し → くすみゴールドの罫線 → サブ → フッター** の順番と間隔は全枚で共通。
罫線が見出しとサブの間に入るのは、**投稿済みの01に合わせたため**。
この塊が同じ形をしているから、置き場所を変えても9枚が1つの作品に見える。

レイアウトは絶対座標ではなく縦のフレックスで組んである。
コピーの行数を増やしても写真と文字は重ならず、写真側が自動で縮む。

### 写真の上に文字を置くとき

**写真は全面に置き、下に明るいアイボリーの帯を立ち上げて、その上に紺文字を読ませる。**
帯の高さはコピーの行数から自動で決まるので、文字が写真に埋もれることはない。

暗いフィルター＋白文字には戻さない。実際の写真で3通り試した結果:

| 試した型 | 結果 |
| --- | --- |
| 白文字・写真を暗くしない | 空の上は読めるが、建物や人に重なった瞬間に崩れる。サブコピーは読めない |
| 白文字・写真を暗くする | 読めるが、空の青と地面の明るさが死ぬ |
| 紺文字・写真の明るい部分に置く | 写真が変わると成立しない（緑の中では完全に読めない） |
| **写真全面＋下に明るい帯** | **どの写真でも読めて、色もそのまま残る** |

写真ごとに文字の位置を変えれば読めるが、それをやると9枚の統一が壊れる。

### 写真は「見える範囲」に合わせて置く

写真の高さはキャンバス全面（1350px）ではなく、**帯の外側の見える範囲**に合わせている。
全面にすると横位置の写真が上下で大きく切れ、拡大率も上がる。
この修正でハワイの写真は1.69倍→0.95倍、マルタは2.66倍→1.42倍になった。

**帯は下の約45%を覆う。** 被写体が写真の下寄りにあると帯に隠れるので、
その場合は `npm run ig:photo --crop=上%,下%` で上を切り落として被写体を持ち上げる。
06のぶどう棚の写真はこれで対応している（`pergola-crop.jpg`）。

## 5. グリッド設計

9枚を並べた状態そのものを1つの作品として設計している。
同じ型が縦にも横にも隣り合わないように配置した。

```
01 下帯      02 文字のみ  03 下帯
04 手順の図  05 上帯      06 箱
07 上帯3枚   08 数字      09 下帯
```

写真は6枚、文字ものは3枚（02・04・08）。

### 文字の置き場所を3種類つくってある

**同じ「写真全面」でも、文字をどこに置くかで印象が変わる。**
全部を同じ位置にすると、統一感を通り越して単調になる。

| place | 見え方 | 選ぶ基準 |
| --- | --- | --- |
| `bottom` | 下に帯。写真は上側 | 被写体が写真の**上寄り**にあるとき |
| `top` | 上に帯。写真は下側 | 被写体が**下寄り**のとき／上部に隠したいものがあるとき |
| `box` | 浮かぶ箱。写真が四方に残る | 縦位置で余白のある写真。雑誌のページのように見える |
| `side` | **縦割り**。左にアイボリー、右に写真 | 縦位置の写真。帯（横割り）と並ぶと向きが変わる |

`side` だけ文字が入る幅が386pxしかない。この型を使う投稿は
**見出しを52〜58pxまで落とし、`headline` を1行6文字くらいに割る**必要がある。
長い行を渡すと勝手に折れて「19年勤めた会／社を、」のような切れ方になる。
フッターは狭い列で重なるので、この型だけ縦に積んでいる。

**帯の位置は好みではなく、写真の被写体がどこにいるかで決まる。**
帯は画面の約45%を覆うので、被写体のある側に帯を置くと人物が隠れる。

05は上に帯を置くことで、背景の棚が文字の裏に入る。
隠したいものが写真の上部にあるときは、この使い方ができる。

### 表紙に番号を入れない理由

当初は全枚に 01〜09 の番号を入れていたが、外した。

**Instagramのプロフィールは新しい投稿が左上に来る。**
01から順に投稿すると、グリッド上では番号がこう並ぶ。

```
09 08 07
06 05 04
03 02 01
```

番号が逆から読まれ、はじめて見た人には左上の「09」が何なのかわからない。
順番はキャプション冒頭の「01｜」で伝えることにして、表紙からは外した。
表紙に残したのはカテゴリー名（LIFE / ABOUT ME / GLOBAL …）だけ。

戻したいときは `cardHTML(post, { numbers: true })` の既定値を変えれば戻る。

投稿前に見るべきグリッドは `grid-instagram.png`（実際の並び）のほう。
`grid.png` は物語の順で、設計を確認するためのもの。

### 04と05の分担

隣り合う2枚なので、役割を分けている。

| | 04 HOW I WORK | 05 AI & SYSTEM |
| --- | --- | --- |
| 見せるもの | **動作**（何をするか） | **場面**（実際に働いている手元） |
| 形 | 線画アイコンを横に並べた図 | 写真＋上に帯 |

04で挙げた4手のうち「AIに任せる／人に任せる」を細かく問い直すのが05の本文。
表紙では図と写真で分けているので、縮小して並べても別物として読める。

1枚直すたびに、必ず `/instagram9` か `grid-instagram.png` に戻って全体を見る。

### 写真を選ぶときに見るところ

**被写体が写真のどこにいるか。** これで置き場所（place）が決まる。

- 被写体が**上寄り** → `bottom`（下に帯）
- 被写体が**下寄り** → `top`（上に帯）
- 縦位置で余白がある → `box`（浮かぶ箱）

どれにも当てはまらないときは `npm run ig:photo --crop=上%,下%` で
被写体の位置ごと動かせる。06はこれで対応している。

`focus`（1枚もの）と `focusBy`（3枚組）で、枠の中のどこを残すかも指定できる。

| --- | --- | --- |
| 並べる順が、持っている人から始まっている | **誰でも持っているものを先に置く** | ×「お客様も、仕事の内容も、時間の使い方も」→ ○「どこで働くかも、誰と働くかも、何を引き受けるかも」 |

**「副業」という言葉で狭めない。** 一度だけ、当てはまる人を増やすために使う。

## 7. 本文（キャプション）

9本とも `src/instagram9/posts.js` に入っている。
`/instagram9` の各投稿に「本文をコピー」ボタンがあり、ハッシュタグまで含めてそのままコピーできる。

### 本文の最後に定型ブロックを置く

9本すべての末尾に、同じブロックを入れている（`PROFILE_FOOTER`）。

```
─────────────
Rie｜仕事を軽くして、人生を広げる。

会社員22年（社長秘書・全社リスクマネジメント統括）
→ オンライン秘書として50件以上の事業を支援
→ 経営者の業務整理・AI活用・仕組み化・チームづくり
```

役割は2つ。

1. **名乗り** — 1投稿だけ見た人に、誰の話かを伝える
2. **経歴** — 言っていることの裏づけ

**「01〜09で、ひとつの物語になっています」は入れない。**
本人が毎回削除していた。連載であることは各本文の頭の「01｜」で足りていて、
説明を足すと**強く閉じた着地のあとに案内文が来て弱くなる。**

1か所直すと9本すべてに反映される。

### ハッシュタグは1投稿5つまで

数を増やすより、その回に本当に合うものだけを置く。
**1枠目はシリーズのタグで固定**し、残り4枠をその回の中身に合わせる。
